# Практическая работа: Аутентификация и разграничение доступа в PostgreSQL

## 🎯 Цель работы
Научиться настраивать аутентификацию в PostgreSQL и создавать пользователей с разграничением доступа к объектам.

## 📋 Задание
1. Настроить файл pg_hba.conf под требования: SCRAM SHA-256 и доступ только из подсети 192.168.1.0/24.
2. Создать схемы, пользователей и разграничить права доступа.
3. Проверить работу прав: INSERT разрешён, SELECT запрещён для User2.

## 🛠️ Использованные инструменты
- PostgreSQL
- pg_hba.conf — конфигурация аутентификации
- SQL: CREATE SCHEMA, CREATE USER, GRANT, CREATE TABLE, INSERT, SELECT

## 📦 Файлы

- [pg_hba.conf](pg_hba.conf) — исправленный конфигурационный файл
- [commands.sql](commands.sql) — все SQL-команды по заданию

## 🌐 Задание 1. Настройка pg_hba.conf

### Исходный файл

# TYPE    DATABASE    USER    ADDRESS         METHOD
local     postgres    all     localhost       trust

### Требования
- Метод аутентификации — SCRAM SHA-256.
- К любой БД могут подключаться только клиенты из подсети 192.168.1.0/24.

### Исправленный файл

# TYPE    DATABASE    USER    ADDRESS             METHOD
local     all         all                         scram-sha-256
host      all         all     192.168.1.0/24      scram-sha-256

### Пояснения

| Поле | Значение | Почему |
|------|----------|--------|
| TYPE | local / host | local — подключение через Unix-сокет, host — через TCP/IP |
| DATABASE | all | Специальная опция all — все базы данных |
| USER | all | Специальная опция all — все пользователи |
| ADDRESS | 192.168.1.0/24 | Ограничение по подсети (только для host) |
| METHOD | scram-sha-256 | Хеширование паролей по алгоритму SCRAM SHA-256 |

### Ключевые моменты
- local — оставлен для локального подключения (например, через psql на самом сервере).
- host — добавлен для сетевых подключений, но только из подсети 192.168.1.0/24. Клиенты из других подсетей не смогут подключиться.
- trust заменён на scram-sha-256 — теперь пароли проверяются по хешу, а не принимаются без проверки.
- Опция all в полях Database и User заменяет перечисление конкретных баз и пользователей.

## 🌐 Задание 2. Создание схем, пользователей и разграничение доступа

### Задание 1. Создание схем

-- Выполняется от имени суперпользователя postgres
CREATE SCHEMA shema1;
CREATE SCHEMA shema2;

Созданы две схемы: shema1 и shema2.

### Задание 2. Создание пользователей

CREATE USER User1 WITH PASSWORD 'password1';
CREATE USER User2 WITH PASSWORD 'password2';

Созданы два пользователя с правом login (по умолчанию CREATE USER создаёт учётную запись с правом входа).

### Задание 3. Права пользователя User1 на схемы

-- Выполняется от имени суперпользователя postgres
GRANT ALL PRIVILEGES ON SCHEMA shema1 TO User1;
GRANT ALL PRIVILEGES ON SCHEMA shema2 TO User1;

User1 получил полные права на схемы shema1 и shema2: может создавать таблицы, изменять, удалять объекты.

### Задание 4. Создание таблицы от имени User1

-- Выполняется от имени пользователя User1
CREATE TABLE shema1.Table1 (
  col1 text
);

User1 создал таблицу Table1 в схеме shema1 с одним столбцом col1 типа text.

### Задание 5. Права User2 на добавление данных

-- Выполняется от имени пользователя User1 (владельца таблицы)
GRANT INSERT ON shema1.Table1 TO User2;

User2 получил право только на INSERT (добавление данных) в таблицу shema1.Table1. Права на SELECT, UPDATE, DELETE не выданы.

### Задание 6. Добавление строки от имени User2

-- Выполняется от имени пользователя User2
INSERT INTO shema1.Table1 (col1) VALUES ('test');
COMMIT;

Строка со значением test успешно добавлена в таблицу. Право INSERT работает.

### Задание 7. Попытка выборки от имени User2

-- Выполняется от имени пользователя User2
SELECT * FROM shema1.Table1;

Результат: ошибка.

Ожидаемый результат:
ERROR: permission denied for table table1

User2 не имеет права SELECT на эту таблицу. Права разграничены корректно: он может только добавлять данные, но не читать их.

### Задание 8. Проверка строки от имени User1

-- Выполняется от имени пользователя User1 (владельца таблицы)
SELECT * FROM shema1.Table1;

Результат: отображается одна строка со значением test в столбце col1.

Это подтверждает: User2 успешно добавил данные, а User1 видит их. Права INSERT и SELECT работают как задумано.

## 📊 Использованные DML-команды

| Команда | Назначение |
|---------|-----------|
| CREATE SCHEMA | Создание схемы |
| CREATE USER | Создание пользователя с паролем |
| GRANT ALL PRIVILEGES ON SCHEMA | Полные права на схему |
| CREATE TABLE | Создание таблицы |
| GRANT INSERT ON | Право добавления данных |
| INSERT INTO | Добавление строки |
| SELECT | Выборка данных |
| COMMIT | Фиксация транзакции |

## 🔐 Практическая значимость
Настройка аутентификации и разграничение доступа — базовые задачи администратора БД и специалиста по ИБ:
- защита БД от несанкционированного доступа (SCRAM SHA-256 вместо trust);
- ограничение доступа по IP-подсети;
- принцип минимальных привилегий — пользователь получает только те права, которые нужны для работы;
- разграничение на уровне схем и таблиц;
- защита персональных данных от чтения неавторизованными пользователями.

В реальной работе эти навыки применяются при настройке PostgreSQL в продакшене, аудите прав доступа и выполнении требований регуляторов (152-ФЗ, PCI DSS).

## ⚠️ Особенности выполнения
- Создание пользователей: CREATE USER по умолчанию создаёт учётную запись с правом login. Дополнительно указывать WITH LOGIN не обязательно.
- Порядок выдачи прав: сначала суперпользователь postgres создаёт схемы и пользователей, потом раздаёт права. Только после этого пользователи могут работать со своими объектами.
- Права на таблицу выдаёт владелец. GRANT INSERT ON shema1.Table1 TO User2 выполняется от имени User1 — владельца таблицы.
- При попытке SELECT от User2 PostgreSQL не выдаёт данные, а возвращает ошибку permission denied.
- COMMIT после INSERT — не обязателен при autocommit, но полезен для явного подтверждения транзакции.
